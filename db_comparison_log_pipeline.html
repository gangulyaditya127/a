🥇 Recommended: ScyllaDB

Write throughput of Cassandra without JVM overhead. Handles 30M rows in under 7 min on a modest cluster. Use composite partition key on (src_ip, dst_ip, dst_port, protocol) — Scylla enforces uniqueness at the partition level, doubling as your DB-side dedup. Pair with Redis for the 10M reference list check pre-insert.

🥈 Runner-up: Cassandra

Same distributed write model as Scylla, more operators in the job market, slightly higher ops overhead (JVM GC pauses can spike). Use if your team already has Cassandra expertise. Same Redis pairing for reference dedup.

Honorable mention: ClickHouse

If storage cost matters a lot (columnar compression is extraordinary on IP/port data), ClickHouse is worth it — but you must handle dedup entirely in your application before inserting. ReplacingMergeTree dedup is async and not suitable for your SLA.

What to avoid here

Postgres and TimescaleDB are great databases — just not for 30M-rows-in-7-minutes with unique constraint checks. MongoDB is in a similar boat unless you shard aggressively, which adds ops pain for no real gain vs Scylla.

* Dedup note for ScyllaDB/Cassandra: model your row key as the 4-tuple (src_ip, dst_ip, dst_port, protocol). A duplicate INSERT with the same key is a no-op — this is your DB-level dedup. The Redis SET handles the external 10M list check before you even attempt insertion.
